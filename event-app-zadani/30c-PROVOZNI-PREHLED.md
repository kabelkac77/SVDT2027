# Provozní pracovní přehled — omezený krok

Implementovat pouze event-app/src/components/operations-panel.tsx. Client export OperationsPanel({edition,crew,userId,onGuardChange}): edition Edition,crew CrewData,userId string,onGuardChange:(guard:()=>boolean)=>void. CrewApp host dodá auth/ročník a zapojí guard do navigace/odhlášení/přepnutí roku. Root panel key userId+edition.id, nesmí uchovávat data minulého účtu. Komponenta používá loadOperations/writeOperation a model/formuláře. Žádná další auth nebo localStorage/demo/import/SQL/účty/zprávy. Nadpisy česky, stávající design/třídy crew-app/panel/crew-form-grid/badge.

## Lifecycle a draft

Effect loadOperations(edition.id), ref generation/cleanup guard, při novém requestu nebo chybě přístupu skrýt stará data. Chybu explicitně ukázat a nabídnout Zkusit načíst znovu. Nepředstírat prázdnou úspěšnou evidenci. Čtení neuděluje práva. Edit úkolů/zón jen admin/coordinator, registrací data.canRegistration, všechny zápisy zakázané v archived edition. Správa grantů jen admin. Generace a alive brání pozdnímu read/write vrátit starý stav. loading/saving chyby zachytit přes operationsMessage. Během saving ref lock brání opakovanému submitu a navigaci.

Draft vybrané entity typovaný {kind,draft}, vlastní dirtyRef. Odchod z tab/view/řádku/filtru/nový/reload chrání window.confirm, během saving zakázaný. Guard zaregistrovat onGuardChange přes effect a cleanup nastaví()=>true; guard kontroluje dirty/saving přes refs, žádný stale closure. Přijaté zahození vymaže draft a dirty. beforeunload když dirty nebo saving. Nový explicitní UUID/verze0 před prvním pokusem. Zápis operationPayload(kind,draft) s fingerprint(kind+edition+JSONpayload), zachovat requestId přes chybějící odpověď/refresh a při stejném těle opakovat stejně. Žádný uuid nový při retry. Po potvrzeném úspěchu načíst nové verze, zachovat vybranou entitu a obnovit draft/verzi, form key id/version. Při chybě nebo konfliktu draft zachovat a nabídnout vědomé zahodit/načíst. Pokud refresh po úspěšném write selže, nezdvojit vytvoření, ponechat request a upozornit. Při write permission error/refetch access error neudržovat citlivé staré registrace (skrýt jejich data a resetoprávnění; draft případně explicitně omezený na nyní nezobrazené údaje bez poskytování dalšímu účtu).
