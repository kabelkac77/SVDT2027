# Sdílená crew — skutečné aplikační rozhraní

Implementovat dva nové soubory event-app/src/components/crew-app.tsx a crew-forms.tsx, obě client components. Model/adapter už jsou hotové a předané. Host doplní route /crew, navigaci, scoped CSS a nezávislé testy. Neimplementovat demo, import, další moduly nebo nové služby.

## CrewApp

Export CrewApp(). Použít stávající supabase(), loadCrewEditions/loadCrew/writeCrew a crew-model. E-mail/heslo přihlášení ke skutečnému klientu, odhlášení. Při chybějící konfiguraci srozumitelná hláška, bez fallbacku. Auth getSession/onAuthStateChange a výběr dostupného ročníku; nulové členství není přístup. Při odhlášení/změně uživatele ihned skrýt původní data, neukázat data starého účtu novému. Ošetřit opožděné odpovědi/generace při změně ročníku nebo účtu. Bez zbytečných příprav, zpráv nebo skutečných účetních operací.

Zachovat vzhled aplikace: app-shell/sidebar/workspace/topbar, Exo/tokeny a existující CSS třídy. Nad tabulkou hledání, filtr stavů, včetně vyřazených, přidání člověka, kategorie/cíle, správa přístupů jen správci. Základní tabulka s osmi sloupci jméno, stav, pozice, kdo řeší, PÁ (od–do), SO (od–do), domluva (jen oprávnění vidí částku; ostatním 'Odměna neveřejná'), rok. Kategorie sbalené defaultně, barevná CSS class cat-0..cat-11 (hodnoty ověřit proti regex) a souhrn stavů filtrovaných záznamů. V záhlaví/vedle názvu zobrazit coverageFor pro celou kategorii a jasně uvést požadovaný termín; not-set Neurčeno, uncertain K ověření, missing Chybí N, covered Cíl pokryt. Není to výpočet směn. Přepnutí vyhledávání nemění skutečný cíl; stavové součty filtrovány, pokrytí počítat nad celou aktuální uloženou kategorií.

Klik na záznam zobrazí detail v dalším tr/td colSpan8 pod ním, nikdy jiná stránka/modal. Rozepsaný nový má klientské crypto.randomUUID id už před prvním pokusem o uložení a version0. Admin/coordinator mohou provozní záznam upravovat, člen má pouze vlastní údaje read-only. Archivovaný ročník je read-only. Roster draft zachovat při chybě a konfliktu, nabídnout vědomé zahození/načtení aktuální verze. Neodesílat další změny současně, použít ref lock i disabled UI. Pro writeCrew držet requestId a fingerprint těla/kind/edition: opakování po nepotvrzené odpovědi se stejným tělem použije totéž requestId, změněné tělo nové. Neresetovat draft, dirty ani requestId při chybě. Po úspěchu znovu načíst serverová data a verze, zobrazit potvrzení, ponechat otevřený řádek. Generace zabrání návratu starých dat při přepnutí účtu/ročníku.

Neuložené změny chránit před změnou ročníku/řádku, filtrů, zavřením detailu a odhlášením. beforeunload při dirty/saving. Při explicitním opuštění je možné jednoduché window.confirm v budoucím lidském UI; žádné přerušování tohoto implementačního běhu. Po odmítnutí potvrzení zůstanou ovládací hodnoty/draft. V případě otevřených settings forem hlídat i jejich dirty stav. Žádné tiché přepsání nebo zahození.
