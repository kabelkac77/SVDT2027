# Běh úplné zálohy — koordinace, šifrování a readback

BackupFile má vždy přesně pracovní tvar `{source:string,path:string,bytes:Buffer}` s cestou začínající `source/`, kompatibilní s backup-bundle.js. Do zdrojového textu nevkládat raw NUL/C0 bajty; regexové kontroly zapisovat textovými escape sekvencemi.

Implementovat pouze `event-app/tools/backup-runner.js`, ESM Node built-ins fs/path/crypto a stávající backup-bundle.js. Knihovna bez CLI/config/scheduleru, žádné skutečné sítě/účty v modelu. Žádné logy nebo klíče do výstupu.

Export `async runBackup({collectors,key,destination,lockPath,consistency})` -> `{version:1,id,sha256,fileCount,byteCount,sourceCounts:{sources:number,crew:number,inputs:number,postgres:number,storage:number,exports:number},remoteReadbackVerified:true}`. id je nové UUID s příponou .svdtbackup, bez uživatelských názvů/cest. key Buffer/Uint8Array přesně32b, kopie. collectors pole `{sources:string[],collect:async()=>({complete:true,files:BackupFile[]})}`. Právě jeden vlastník každého REQUIRED_SOURCES, žádný chybějící/duplicitní/neznámý zdroj, source skupiny neprázdné. Místní crew a exports mohou být jeden kolektor/snapshot. collect funkce musí existovat, result complete literaltrue a files array. Každý výsledný file.source patří do sources vlastníka. Neprázdné zdroje vyžaduje createBackup, storage může být explicitně známě prázdné. Žádný fallback po erroru.

consistency má async acquire(), které před prvním sběrem získá operátorem implementované konzistentní okno a vrátí async release() funkci. Chybí-li funkce nebo release není funkce => BACKUP_JOB_NOT_READY a žádný upload. No-op adapter v testu není důkaz produkčního uzamčení DB/Storage. Běžet sekvenčně, release vfinally přesně jednou i při chybě. Pokud release selže, běh selže bez uploadu. Nezačít upload před ukončením sběru a úspěšným release.

destination má `{kind:'remote',putExclusive:async(id,encryptedBytes)=>void,read:async(id)=>Buffer|Uint8Array}`. Kind local/iCloud folder se nepovažuje za ověřený remote adapter. Žádný automatický overwrite/delete/retention. Exkluzivitu vložení musí skutečný adapter vynucovat na serveru; zde explicitní smlouva, ne ověření poskytovatele. Nenahrazovat předaný provider ani nekonstruovat klienta z .env. Chybějící capability=>NOT_READY bez sběru. Nikdy neposílat AESkey nebo plaintext destination metodám, jen nový id a šifrovaný bundle. Vlastní kopie Bufferů vůči mutaci adaptérem: hash a readback nemá být možné ovlivnit změnou stejného sdílenéhoBufferu.

lockPath absolutní v existujícím skutečném parentdir bez koncového symlinku, soukromý lock O_WRONLY|O_CREAT|O_EXCL0600. Už existuje (i symlink nebo cizí process) => Error('BACKUP_JOB_LOCKED'), žádné automatické odstranění stale locku. Zapsat jen náhodné runid a procesid, žádná data nebo klíče, fsync, fd držet do konce. Zapamatovat dev/ino, finally close a unlink pouze při stále shodném inode; nikdy nemazat cizí náhradu. Nezakládat cizíparentdir. Před získáním locku ověřit všechny statické options/klíč/capabilities; chybějící config nic nesbírá/nepublikuje.

Po úplném sběru createBackup(files,sources,key), vlastní readBackup před uploadem ověří finálníbalíček a vrácené počty počítat podleověřenéhomanifestu. Vygenerovat id crypto.randomUUID(), hashSHA256 šifrovanéhobufferu. Upload putExclusive(id,copyofbundle), poté nezávislé read(id); vrácené bytes musíbyt Buffer/Uint8Array, mít stejnou délku/sha256 a projítreadBackup s původnímklíčem. Až pakúspěšnýreturn. Upravováníindexu 'last success'/retence nebo hlášení úspěchu předreadback není dovoleno. Přiupload/readbackchybě ponechatpředchozívzdálenékopie, nicnemazat (novýneověřenýobjektjepropozdějšíaudit). Kroky nemají vlastníslepréretry.

Chyby jen Error('BACKUP_JOB_NOT_READY'|'BACKUP_JOB_LOCKED'|'BACKUP_JOB_FAILED'), žádné raw child/provider/file/crypto chyby. Crypto klíč lokálníkopiivfinallyfill0, původnícallerklíčneměnit.
