# Storage — kontrola inventáře jako menší samostatný krok

Účel: část29e bez download, crypto, filesystemu, CLI nebo přístupů. Implementovat pouze `event-app/tools/backup-storage-inventory.js` jako ESM bez závislostí. Exporty `validateInventory(inventory)` sync a `listStorageInventory(storage)` async. Výjimky vždy `Error('BACKUP_STORAGE_FAILED')`, žádné logy. Nepoužívat raw NUL/C0 ve zdroji, jen textové escape sekvence. Completed s questions=[], neblokující budoucí poznámky jen summary.

Oba exporty vracejí novou nezávislou strukturu `{buckets:[{id,objects:[{key,id,updated_at,size,version?}],metadata?}]}` v deterministickém pořadí přes porovnání `<`/`>` bez localeCompare. Metadata v síťovém inventáři whitelistují `public:boolean`, `allowed_mime_types:null|string[]`, `file_size_limit:null|number|string` pro obnovu. Chybějící nepovinná metadata nemusí být v objektu. Autoritativní objekty navíc zachovají optional `sha256` (64lowerhex). Kopírovat pouze whitelistovaná pole, nevkládat cizí odpověď do manifestu. Autoritativní inventory vyžaduje `complete === true` a buckets pole. Celkem nejvýše9999objektů a128MiB podle size, prázdný úplný inventář platí. Nejvýše10000bucketů; manifest plus9999bajtových objektů musí později splnit společný limit runneru.

Klíče: id bucketu bezpečný jeden relativní POSIX segment, key bezpečná relativní POSIX cesta bez prázdných/./.. segmentů, slash na začátku, backslash, C0/DEL, lone UTF16 surrogates; max1000znaků aUTF8 segment<=255. Zachovat case/Unicode, nedělat normalizaci ani přejmenování. bucket id/objekt key duplicity porovnávat přesně přes Map/Set. `id` objektu a`updated_at` jsou neprázdné texty bez control/loneUTF16. `size` safe integer>=0. Optional version je neprázdná textová identita aktuálního objektu, zachovat. Do nového výstupu nekopírovat nested input arrays referencí.

`storage.listBuckets({limit:1000,offset:N,sortColumn:'id',sortOrder:'asc'}) -> {data:Bucket[],error}`: stránkovat do stránky<1000, max1000stránek, odmítnout duplicateid a malformed/error/throw. Podporované pouze type absent nebo'STANDARD'; explicitní is_versioned:true / archived_at / delete marker odmítnout také u bucketu. Ověřit volitelná metadata, vrátit je beze ztráty validních hodnot. Limit10000bucketů chrání paměť před neomezeným listem.

Pro každý bucket `storage.from(id).listV2({prefix:'',limit:1000,with_delimiter:false,cursor?:string}) -> {data:{hasNext:boolean,nextCursor?:string,folders:[],objects:[{id,name,key?,updated_at,metadata:{size},version?,archived_at?,is_versioned?,is_delete_marker?}]},error}`. Vždy data ve správném tvaru, folders prázdné. Stránka max1000objektů. Použít key pokud existuje, jinakname. Při hasNext true musí být nová neprázdná kurzorová hodnota a neprázdná stránka; zakázat opakování/cykly, max1000stránek. hasNext musí být boolean. Odmítnout unsupported archivované/is_versioned/delete marker objekty. Všechny objekty projdou stejnou kontrolou a limity jako authority. Služba může být RLS omezená: výstup listStorageInventory nikdy netvrdí complete:true a sám není důkaz úplnosti. Porovnání s nezávislou autoritou a opakovaný list řeší29e.
