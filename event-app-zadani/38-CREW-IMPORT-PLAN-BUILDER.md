# Malý čistý builder plánu počátečního importu crew

Implementovat pouze `event-app/tools/crew_import_plan.py`, standard library + existující `build_preview` a `reconcile_preview` ze sousedních modulů. Host nastaví tools na sys.path. Export `build_import_plan(tables_bytes,mapping=None,target=None)` -> dict. Žádný FS/network/DB/SQL/CLI/log/UUID generátor, žádný skutečný import nebo data v modelu. Všechny chyby ValueError('CREW_IMPORT_PLAN_FAILED') fromNone. Výsledek vždy mode:'plan_preparation',applyReady:false, i když planText existuje. completed questions=[], neblokující budoucí poznámky pouze summary. Nepřidávat jiné soubory.

## Existující rozhraní (dostačuje, nemusíte číst celé moduly)

build_preview(tables_bytes) -> `{version:1,mode:'preview_only',applyReady:false,sourceSha256:64hex,categories:[{sourceCategoryId,name,color,sortOrder,sourceVersion,requiredCount:null,requiredTerm:''}],entries:[{sourceRowId,sourceCategoryId,sourceId,sourceVersion,updatedAt,roster,compensation,unmapped}],preservedTables:[...],warnings:[...],blockers:[...]}`. entries je plochý list; lokální sourceRowId a sourceCategoryId jsou unikátní stringy. Helper už validuje celý zdroj, textové roky2027/2026, moneyhaléřeNULL/0, limity a původní tabulky.

entry.roster přesně kind:'unresolved',person_id:null,linked_user_id:null,name,position,owner_label,email,phone,status,term,friday,saturday,notes (texty),archived(bool). entry.compensation přesně estimate/agreed/total/paid:null|int0..99999999999,barter/merchstrings. Nepřepočítávat/neořezávat source hodnoty. Nepřevádět statusNote/contactOriginal do notes.

reconcile_preview(tables_bytes,flat_mapping=None,target=None) validuje úplný target a reference. flat_mapping je `{editionId:UUID,categories:{localCat:UUID},entries:{localRow:UUID}}`. target je přesně kompletní serverový snapshot: complete:true,canReadCompensation:true,provenanceReady:bool,capturedAt:nonemptystr,edition:{id:canonicalUUID,year:2027int,archived:bool}, categories:[{id,edition_id,name,color,version,...}],entries:[{id,edition_id,category_id,version,...všechna rosterpole}],compensation:[{roster_id,edition_id,version,...všechna compensationpole}],sourcePackages:[{id,edition_id,source_sha256}],sourceLinks:[{package_id,edition_id,source_row_id,roster_id}]. Všechny verze positive nonboolint. Kompenzace nemusí existovat pro dosud nevyplněný roster, její nullableklíče pokud rowexistuje jsou povinné. Kategorie goal required_count/required_term se ignoruje a musí zůstat. Nový server doplní `targetFingerprint:64lowerhex`. To je SHA z PostgreSQL JSONB bezcapturedAt, nikoli Python hash target objektu; pouze převzít otisk a neprohlašovat jej za nezávisle ověřené oprávnění. Oba helpery chybují ValueError se svými kódy, vždy zabalit do CREW_IMPORT_PLAN_FAILED.

reconcile report má rows:[{sourceRowId,targetRosterId,status,fields}],categories:[{sourceCategoryId,targetCategoryId,status,fields}],sourcePackageSeen a blockers. Reportstatusmissing_target při explicitním create je očekávaný, ne automatická chyba. Helper validuje types/reference/duplicates/cizí edition; nevydávat jeho matches za aktivační souhlas.

## Explicitní mapping builderu

None nebo neúplný mapping -> vrátit blocker MAPPING_REQUIRED, planText:null,planSha256:null; žádné defaultní asociace. Pokud mapping dodaný, přesně `{editionId:UUID,categories:{localCat:{id:UUID,action:'create'|'keep'}},entries:{localRow:{id:UUID,action:'create'|'keep',compensationAction:'create'|'keep',kind?:'group'|'unresolved'}}}`. Canonical lowercase non-nil UUID, klíče musejí existovat ve zdroji, žádné duplicate cílovéID v kategoriích nebo rosteru. Extra klíče v mappingu nebo v item objektech odmítnout. kind je POVINNÉ pouze u create a u keep NESMÍ být dodané (keep zachová identitu cíle). create roster vyžaduje compensationAction:create. Neprovádět slučování podle jména/kontaktu.

TargetNone -> blocker TARGET_EXPORT_REQUIRED a PRIVATE_PROVENANCE_SCHEMA_REQUIRED, žádný plán; mapping pořád validovat pokud dodaný. Targetmalformed/partial -> chyba, nikdy náhrada prázdnouDB. Pro dostupný target zavolat reconcile_preview s flat mappingem nebo None. Navíc vyžadovat správný targetFingerprint64hex; bez něj blocker TARGET_FINGERPRINT_REQUIRED, žádný plán. archivedTrue -> TARGET_ARCHIVED, provenanceReadyFalse -> PRIVATE_PROVENANCE_SCHEMA_REQUIRED. sourcePackageSeenTrue -> SOURCE_ALREADY_PRESENT_REVIEW_REQUIRED (V1 nevytváří duplicitní import stejného zdroje). Vždy chybějící kategorie/rowmapping brání planText.

## Příprava operací

categories ve stejném pořadí jako preview: `{sourceCategoryId,targetCategoryId,action,expectedVersion}`. create pouze pokud targetcategoryID není v exportu, expectedVersion0; keep vyžaduje existenci a přesnou shodu name/color, expectedVersion kopie serverové verze. Potřebné počty/termíny se do plánu NEPÍŠOU.

entries ve stejném pořadí jako preview: `{sourceRowId,targetRosterId,action,expectedVersion,compensationAction,expectedCompensationVersion,kind,personId,linkedUserId}`. create: IDnení vtargetu, verze0,kind z explicitního mappingu(group/unresolved),personId/linkedUserIdnull. keep: IDexistuje, sourcecategory targetID existuje nebo je plánované create, category_id musí souhlasit, všechna původní roster pole (mimo kind/person_id/linked_user_id) přesně shodná. Kind/personId/linkedUserId KOPÍROVAT z cíle včetně person typu, nikdy je neměnit; expectedVersion z cíle. Odlišná zachovaná identita sama není konflikt, protože se nepřepisuje. U původního linkedUser neaktivovat/nezaložit členství.

compensationAction:create vyžaduje chybějící finanční row, expectedCompensationVersion0. keep vyžaduje existenci, přesnou shodu6kompenzačních hodnot a verzi z cíle; NULL není0. create+keep zakázané, keep+create povolené a znamená explicitní doplnění chybějící odměny, nikoli přepsání. Jakýkoli konflikt createID/existence, keep/obsah nebo kategoriální vazba -> blocker TARGET_CONFLICTS, žádný plán. V1 nikdy nevytvoří UPDATE/overwrite.

## Výstup a otisk

Výstup `{version:1,mode:'plan_preparation',applyReady:false,sourceSha256,targetFingerprint:hex|None,planText:str|None,planSha256:hex|None,counts:{categories,entries},blockers:[sorted unique codes]}`. Vždy OPERATOR_APPROVAL_REQUIRED,VERIFIED_BACKUP_AND_RESTORE_REQUIRED,EXPLICIT_ACTIVATION_REQUIRED. Nedostupné vstupy a konflikty mají navíc výše určené blocker kódy. Pokud není žádný další blocker, připravit planText přes json.dumps(ensure_ascii=False,sort_keys=True,separators=(',',':'),allow_nan=False) s přesnými6top-level klíči `{version:1,editionId,sourceSha256,targetFingerprint,categories:[...],entries:[...]}` a SHA256 UTF8 tohoto přesného textu. U úspěšně připraveného plánu stále zůstávají3ruční brány a applyReady:false. Limitplan16MiB, nic nezkracovat. Plán obsahuje jen lokální/target ID, explicitní akce/verze/identitu a hashe, nikoli jména/kontakty/částky/rawsource. Výstup je přesto soukromý0600, ne veřejný artefakt.

Cílové UUID dodává až později operátor podle ručního mapování. Neexistující target nebo mapping se nesmí doplnit náhodnými UUID nebo create-defaulty. Žádné volání schválení nebo import RPC, žádné nové účty/osoby/role. Host nezávisle testuje a reviewuje. Všechny reálné brány zůstávají odložené v31/37.
